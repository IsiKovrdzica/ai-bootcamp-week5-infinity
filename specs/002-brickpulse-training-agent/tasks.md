## Non-negotiable execution protocol

Every implementation slice below is a gated TDD slice. T03 initializes `docs/EVIDENCE_W05.md` and `docs/AI_USAGE_LOG_W05.md` before implementation slices begin, with structure/header and only facts known then. Every later slice must append its observed evidence contemporaneously before its commit gate: exact prompt/purpose where relevant; accepted/rejected AI proposal or decision; files/interfaces inspected; expectation/test written first; exact focused command actually run; observed RED result and reason; implementation performed; exact GREEN result; relevant regression result; manual diff/security review; pair decision/approval; and commit hash after the approved commit. Never report an unrun command as passing.

All future Week 05 commits must contain exactly this trailer, once:

```text
Co-authored-by: Mateja Miletic <miletic.matejamiletic.mateja@gmail.com>
```

No task may read, alter, log, search, move, or expose `.env` or any secret. Routine verification is fake/offline only. `GEMINI_API_KEY` may be named only as an environment-variable name; its value must never appear in tests, evidence, logs, diffs, screenshots, commits, or reports.

**Parallelism rule:** Tasks labelled **Parallel** are safe only after their listed predecessors are complete and only when the assignees do not edit the same files. All other tasks are sequential. `Approval gate` means a human pair must approve before the next slice begins. `Commit gate` means no commit occurs until the task's acceptance condition and the slice protocol are complete.
